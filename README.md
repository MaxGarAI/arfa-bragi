# Арфа Браги: сага скальда

Существующий сайт и игра запускаются одним Flask-приложением. Python 3.11+.

```powershell
cd brewery-game
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
$env:SECRET_KEY = 'замените-на-длинную-случайную-строку'
$env:ADMIN_PASSWORD = 'замените-на-сильный-пароль'
flask --app app run
```

Откройте http://127.0.0.1:5000/ — сайт, /game — игра, /admin/promos — список кодов. Имя в запросе пароля администратора любое. `python seed.py` добавит тестовых игроков. SQLite создаётся автоматически в `game.sqlite3`; регулярно сохраняйте резервную копию. Игрок привязан к cookie браузера, без учётной записи восстановить прогресс на другом устройстве нельзя. Локальная копия профиля используется для отображения, источником данных служит сервер.

Настройки через переменные окружения: `SHOP_URL` (по умолчанию `/#assortment`), `ADMIN_PASSWORD` (без него админка отключена), `SECRET_KEY` (обязателен постоянный секрет для сохранения сессий между перезапусками), `PROMO_COST` (по умолчанию 500), `DATABASE` (путь к SQLite). В интерфейсе указана скидка 10%; согласуйте условия акции перед запуском. Код проверяется и погашается сотрудником в админке; сайт принимает предзаказ через WhatsApp и не поддерживает автоматическое применение скидки.

Для публикации используйте HTTPS, постоянные `SECRET_KEY` и `ADMIN_PASSWORD`, защищённую базу с резервными копиями и WSGI-сервер, например `waitress-serve --listen=127.0.0.1:8000 app:app` за HTTPS reverse proxy. Ограничьте доступ к админке и настройте ограничения частоты запросов на прокси. Приложение должно обслуживать и сайт, и игру на одном домене. Обычный статический хостинг не выполняет Python. Проверка результата ограничивает частоту и длительность сессии, но не исключает автоматизацию; перед выдачей реальных скидок необходима дополнительная защита и контроль акции.

## Тест на Render

`render.yaml` описывает бесплатный веб-сервис и бесплатную базу PostgreSQL. Загрузите проект в GitHub, в Render создайте Blueprint из репозитория и проверьте настройки перед созданием. `DATABASE_URL` подключается автоматически; `SECRET_KEY` и `ADMIN_PASSWORD` генерируются Render. Пароль администратора доступен в настройках переменных окружения сервиса. Адрес сайта будет указан в панели Render. Бесплатная база Render истекает через 30 дней; до окончания срока экспортируйте данные и перенесите их или перейдите на платную базу. Бесплатный сервис засыпает после 15 минут простоя, и первое открытие может занять около минуты. PostgreSQL-конфигурация подготовлена, но до развертывания её нужно проверить на работающей базе.
